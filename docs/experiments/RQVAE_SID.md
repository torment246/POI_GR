# RQ-VAE 与 SID 实验

本文件记录从 POI Embedding 到离散 Semantic ID 的正式实验，包括 RQ-VAE、RQ-KMeans、碰撞分析、GID 与完整 SID。SFT 和生成式检索实验不记录在本文件中。

## 当前状态

- 已完成 Vanilla RQ-VAE 首轮北京全量容量对比、Geohash6 Geo-Semantic PID 评估及确定性 Dedup 映射，正式实验为 `EXP-20260723-01（SID-002）`、`EXP-20260723-02（PID-001）` 和 `EXP-20260723-03（PID-002）`。
- 当前基线固定使用 Qwen3-Embedding-0.6B；三组模型均训练满 50 epoch，并完成 epoch 20/30/40/50 共 12 组全量 SID 评估。
- 已确认 `BJ-RQVAE-1024x3 / epoch 20` 为当前语义 SID 主基线，并完成 2,337,178 条 POI 的 Geohash6 GID、九层 base PID 与唯一 POI-PID 映射。
- 下游订单 SFT 与 Trie 约束评测已开展并记录在 `SFT.md`；SID/PID 阶段尚未进入增量 Dedup 更新或 RQ-KMeans 对照。

### 配置与命令

- 模型：`1024 -> 512 -> 256` Encoder、三层 residual quantization、`256 -> 512 -> 1024` Decoder；latent dimension 256。
- 优化：Adam，learning rate `1e-3`，weight decay `0`，reconstruction + `1.0 × codebook` + `0.25 × commitment`，seed 42。
- 训练：batch size 4096，50 epoch，关闭 early stopping；固定保存 epoch 20/30/40/50，并保留恢复状态。
- 初始化：Faiss GPU KMeans，每层 20 iterations；监控与 full SID 评估均使用相同类别和 Case 参数。
- 训练耗时：256×3 为 2,231.03 秒（37:11），512×3 为 1,958.34 秒（32:38），1024×3 为 1,946.92 秒（32:27）；三组 `stop_reason=max_epochs`。
- 训练命令模板为 `python scripts/train_rqvae.py --experiment <EXPERIMENT>`；512×3 与 1024×3 后台执行时仅附加不影响协议的 `--no-progress`。
- 全量导出统一使用 batch size 65,536；每个 checkpoint 的命令模板如下：

~~~bash
python scripts/export_rqvae_sid.py \
  --run-dir outputs/sid/rqvae/<EXPERIMENT> \
  --checkpoint checkpoint_epoch_<EPOCH>.pt \
  --output-dir outputs/sid/rqvae/<EXPERIMENT>/evaluations/epoch_<EPOCH> \
  --device cuda \
  --batch-size 65536
~~~

### 产物、Case 与结论

- 每个 checkpoint 的产物目录为 `outputs/sid/rqvae/<EXPERIMENT>/evaluations/epoch_<EPOCH>/`，且只包含 `sid_codes.npy`、`sid_manifest.json`、`metrics.json`、`collision_cases.jsonl`；12 组共 48 个文件，无临时文件残留。
- 每组输出 20 个热点碰撞 Case，均因桶大小超过单 Case 的 20 条 POI 上限而标记为截断。文档不记录真实 POI 样本；具体人工核验内容保留在各组 `collision_cases.jsonl`。
- 1024×3 相比 512×3 和 256×3 显著提升 reconstruction cosine、full distinct SID ratio、P99 和 Prefix2/3 类别纯度；但最好的 full distinct SID ratio 仍只有 68.53%，colliding POI ratio 仍为 46.24%。
- 第一层存在稳定的低利用率：256×3、512×3、1024×3 分别只使用 104、169、264 个 L1 Token，对应 40.62%、33.01%、25.78%；容量增大时比例下降，不能据此认为码本已充分使用。
- 监控子集 distinct SID ratio 为 94.52%～98.85%，明显高于全量 26.96%～68.53%。碰撞比例依赖样本规模，23,372 行监控值不能替代 2,337,178 行全量值。
- Prefix3 macro purity 会受到大量 singleton 和小桶影响，不能脱离桶大小与 micro purity 单独解释为语义层级质量。
- checkpoint 指标不单调：256×3 的 full distinct ratio 随 epoch 改善，而 512×3、1024×3 均是 epoch 20 最好；reconstruction cosine 又随容量和训练进度略有改善。因此本实验只汇总，不自动选择 checkpoint，等待人工审核。

### 碰撞 Case 分析口径

- 分析对象仅为 `BJ-RQVAE-512x3` 与 `BJ-RQVAE-1024x3` 的 epoch 20 全量 SID。Top 20 按完整 SID 桶大小降序、SID 字典序打破平局，并通过 POI ID 回表读取桶内全部成员；没有使用截断的 `collision_cases.jsonl` 代替完整桶。
- 标准化名称采用 Unicode NFKC、大小写折叠并移除空白和标点；Top 类别占比以非缺失 `category_code` 为分母。主表没有独立行政区字段，“涉及区域”按地址中可识别的北京行政区统计，未识别项单列。
- Geohash6 仅由原始经纬度即时计算用于分析，不写回 SID；最大地理跨度为有效坐标之间精确的最大两两 Haversine 距离。本分析不包含路径健康分析、GID 构建或 SID 修改。
