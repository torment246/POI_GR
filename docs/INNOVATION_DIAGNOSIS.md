# 现有创新实验未超过三篇论文基线的原因分析与后续方向

## 1. 文档定位

- 分析日期：2026-08-19
- 文档性质：跨方法实验诊断与决策参考，不是新的正式实验记录，不新增实验编号。
- 分析范围：只使用仓库中已经完成并登记的 Embedding、SID、SFT、Teacher-Forcing、无约束生成、合法路径约束、候选轨迹、基础 Bucket 与专项评测结果。
- 边界：未运行的设想统一标为“建议”或“待验证”，不把预期收益写成实验结论；各实验的配置、命令、产物和哈希仍以对应方法文档为准。

本文件重点回答四个问题：

1. 当前固定 10,000 条 Validation 是否已经无法继续提升；
2. E4、RQ-KMeans、QGR/GHR 等自研方向为什么没有稳定超过三篇论文复现基线；
3. 现有结果中哪些不是失败，而是收益没有传到最终生成指标；
4. 下一阶段应停止什么、保留什么，以及最值得优先验证的创新主线是什么。

## 2. 核心结论

当前证据不支持“评测集已经饱和，因此所有方法都无法超过论文基线”。更准确的结论是：

1. **主要问题是优化目标错位。**现有创新大多优化 POI 连续表示、全目录等权唯一率、重构误差、类别纯度或静态关系覆盖；最终指标却取决于 `Query + GID + History` 条件下完整标识符的自回归可预测性和 Beam 内排序。
2. **创新信号并非全部无效。**E4 显著提升连续向量召回；E4 RQ-KMeans 的前三层 Teacher-Forcing 累计准确率高于 TIGER；BGE + RQ-KMeans 与 TIGER 在固定 10k 上基本持平。但这些都还没有超过三篇论文复现结果中的最强指标包络，不能算自研创新已经成立。
3. **收益主要被唯一后缀、请求热点碰撞和序列化成本抵消。**静态 SID 更唯一，并不代表真实请求目标更少碰撞；关系更丰富，也不代表 Query 中存在足够信息生成这些关系。
4. **固定 10k 不是性能上限，但已逐渐成为开发集。**它适合日常回归和同协议比较，不足以独立支撑亚百分点胜负，也不能代表长尾、新 Query、no-result、跨城和重复 POI 等专项问题。
5. **后续主线应从“更唯一的静态 SID”转向“Query 可预测的分层 SID + 桶内条件排序”。**先生成可学习的语义桶，再使用 Query、GID、历史、热度和关系特征解决桶内实体排序，比继续增加必须生成的唯一后缀更符合当前证据，也与第一版方案的碰撞展开设计一致。
6. **TIGER、GNPR 和 GenPOI 都是论文复现基线。**Centered GenPOI 的复杂地理收益只能证明数据仍有可提升空间，并给出新的论文基线目标，不能计入本项目自研创新成果。
7. **Bucket 诊断已把路线收敛到容量后移的粗桶生成 + 条件排序。**TIGER 的唯一 Bucket HR@1/10 为 55.53/88.06%；E4+RQ-KMeans `512×1024×2048` 提高到 59.69/88.45%。HR@1/3/5 的配对区间为正，HR@10 的 `+0.39pp` 区间跨 0；同时目标碰撞桶请求升至 52.77%。这说明容量后移改善的是前排粗桶可预测性，Top-10 欠覆盖和桶内实体选择仍未解决，下一步只做冻结候选的轻量排序门禁。

## 3. 三篇论文基线与当前创新结果

以下均为固定 10,000 条 Validation、epoch 3、Beam=10 的主结果。TIGER、GNPR、RQ-KMeans 和 GHR 使用无约束主口径；Centered GenPOI 使用其论文复现链路的 TCG + SSP。因此该表可以比较完整方法系统，但不能把差异直接归因于某一个模块。

| 类型 | 方法 | HR@1 | HR@10 | NDCG@10 | 相对论文最强包络 HR@1 / HR@10 / NDCG@10 | 当前判断 |
|---|---|---:|---:|---:|---:|---|
| 论文复现 | TIGER | 51.87% | 87.16% | 70.4190% | -0.11 / -0.67 / -0.3240pp | 最强固定长度无约束结构基线 |
| 论文复现 | GNPR `512³` | 49.66% | 83.07% | 67.2390% | -2.32 / -4.76 / -3.5040pp | 地图适配版根前缀可预测性不足，但仍属于必须报告的论文基线 |
| 论文复现 | **Centered GenPOI** | **51.98%** | **87.83%** | **70.7430%** | **0 / 0 / 0pp** | 当前普通固定 10k 的论文最强数值包络 |
| 自研创新 | BGE + RQ-KMeans `1024³` | 51.83% | 86.72% | 70.1553% | -0.15 / -1.11 / -0.5877pp | 与 TIGER 接近，但尚未超过论文最强包络 |
| 自研创新 | E4 + RQ-VAE `1024³` | 49.81% | 86.16% | 68.9340% | -2.17 / -1.67 / -1.8090pp | 连续向量收益未传到生成端 |
| 自研创新 | E4 + RQ-KMeans `2048×1024×512` | 50.47% | 87.01% | 69.6711% | -1.51 / -0.82 / -1.0719pp | Top-10 接近 TIGER，但仍低于 GenPOI 和论文包络 |
| 自研创新 | GHR EXP-09 | 50.42% | 82.61% | 67.2405% | -1.56 / -5.22 / -3.5025pp | 静态关系收益没有抵消变长生成成本 |
| 自研创新 | GHR EXP-14 | 49.10% | 79.70% | 65.2636% | -2.88 / -8.13 / -5.4794pp | 更长关系树进一步损害生成与排序 |

这里的“论文最强包络”不是只选择一个方便超过的方法，而是对 TIGER、GNPR、Centered GenPOI 三个复现结果逐指标取最强值。当前普通固定 10k 的 HR@1、HR@10 和 NDCG@10 都由 Centered GenPOI 数值领先，因此自研方法至少要面对 `51.98%/87.83%/70.7430%` 这条完整方法基线，而不能只以 GNPR 或 TIGER 的单项结果作为成功线。

### 3.1 自研创新的验收口径

后续“超过论文基线”应区分两种主张：

1. **通用方法提升：**在普通流量固定集、独立 Validation 确认集和最终 Test 上，主指标 NDCG@10 超过三篇论文最强包络，同时 HR@1/HR@10 不出现有意义回退；差异需要逐样本配对置信区间支持。
2. **专项场景提升：**如果方法明确只解决复杂地理、未见 Query、长尾或碰撞 POI，可以在预先冻结的专项集上与三篇论文全部比较，并超过该专项集的逐指标最强包络；此时只能声明专项提升，不能写成通用性能全面超过三篇论文。

普通固定 10k 上，Centered GenPOI 的小幅数值领先尚未通过配对显著性验证，但它仍应作为保守验收线。不能因为其协议包含 SSP/TCG 就从完整系统对照中删除；正确做法是同时提供：

- 完整方法对完整论文基线的最终比较；
- 同 SID、同约束或同排序协议的模块消融，用于解释提升来自哪里；
- Valid ID、时延、Beam 和候选规模，防止只通过更强推理约束换取不可比的指标。

复杂地理 Query 集的论文基线包络不是单一方法独占：HR@1 最强是 TIGER 64.52%，HR@3/5/10 和 NDCG@10 最强是 Centered GenPOI 的 80.36%/84.80%/88.97%/76.7836%。后续地理创新若要声称全面超过三篇论文，应同时越过这些逐指标最强值，而不只是超过其中一个方法。

合法路径诊断也没有改变总体判断：

- TIGER 合法路径 HR@1/HR@10/NDCG@10 为 52.17%/87.99%/70.9493%；
- BGE + RQ-KMeans 为 52.20%/87.41%/70.6185%，仍属于亚百分点近似持平；
- E4 + RQ-KMeans 前移布局为 50.93%/88.08%/70.4071%，Top-10 略高但 Top-1/NDCG 仍低；
- GHR EXP-09/14 在 Valid ID 达到 100% 后反而下降到 47.20%/75.05%/61.8429% 和 45.92%/71.35%/59.3719%，说明“全部合法”不能替代正确排序。

BGE + RQ-KMeans 的约束 HR@1 52.20% 和部分 E4 容量布局的约束 HR@10 88.08%—88.12% 数值上越过了普通集论文包络的单个指标，但相应 HR@10/NDCG 或 HR@1/NDCG 仍低，而且解码协议不同。因此它们是有价值的局部信号，不构成自研方法已经整体超过三篇论文的证据。

## 4. 固定 10k 是否已经无法提升

### 4.1 没有饱和证据

TIGER 的 HR@1 为 51.87%，仍有 48.13 个百分点的理论未命中空间；HR@10 为 87.16%，仍有 12.84 个百分点的未覆盖空间。虽然其中一部分来自标签歧义和不可观测信息，当前结果仍远未达到可以称为饱和的水平。

复杂地理 Query 专项集提供了更直接的反例：

| 方法 | HR@1 | HR@3 | HR@5 | HR@10 | NDCG@10 |
|---|---:|---:|---:|---:|---:|
| TIGER | **64.52%** | 79.79% | 83.86% | 87.17% | 76.3827% |
| Centered GenPOI | 63.63% | **80.36%** | **84.80%** | **88.97%** | **76.7836%** |

Centered GenPOI 在 HR@3/5/10 和 NDCG@10 上超过 TIGER，HR@10 提高 1.80pp，证明针对目标场景设计的方法可以在现有数据中产生增量。它同时在 HR@1 落后 0.89pp，说明地理模块主要改善候选覆盖，还没有解决实体级精排。这里的 GenPOI 仍是论文复现基线，该结果只用于否定“数据集不可提升”，不计作自研创新成果。

### 4.2 固定集更像自然流量开发集

当前固定集来自 2026-07-13 Validation，以最低 `sample_id` 字典序确定性选择 10,000 条，包含：

- 7,468 个唯一 Query；
- 7,520 个唯一目标 POI；
- 8,399 条 Query 文本在 Train 中出现过；
- 7,691 条精确 `Query–目标 POI` 对在 Train 中出现过；
- 9,693 条样本的目标 POI 有 Train Query 聚合覆盖。

这不是订单泄漏，但反映了真实线上流量中的头部与重复现象。它适合评价整体主流量和历史反馈增强，却会稀释只面向未见 Query、长尾、新 POI、复杂地理或 no-result 的专项收益。

尤其是 96.93% 的固定样本目标具备 Train Query 聚合覆盖，因此当前固定集实际上有利于 E4，而不是对 E4 不公平。E4 仍未转化为生成提升，不能主要归因于评测集没有覆盖其目标对象。

### 4.3 10k 无法稳定判断亚百分点差异

不利用同一样本配对相关性时，TIGER HR@1 的粗略二项 95% 区间约为 `±0.98pp`，HR@10 约为 `±0.66pp`。因此：

- Centered GenPOI 相对 TIGER 的 `+0.11/+0.67/+0.3240pp` 只能称为数值略高；
- BGE + RQ-KMeans 的 `-0.04/-0.44/-0.2637pp` 只能称为基本持平；
- GNPR、GHR 和部分 E4 组合的 1—7pp 下降则不能全部解释为采样误差。

相同业务样本上的 paired bootstrap 或 McNemar 检验通常比上述独立近似更敏感，但当前生成评测产物主要保存聚合直方图和有限错误 Case，没有保存全部 10,000 条的 target rank，无法直接从现有文件完成严格配对检验。后续评测应保存逐样本目标排名和候选摘要。

### 4.4 完整 Validation 的正确用途

完整 597,421 条 Validation 可以：

- 降低亚百分点差异的不确定性；
- 支持按 Query 是否见过、目标热度、碰撞桶、地理复杂度和重复实体分组；
- 检查固定 10k 是否存在偶然分布偏差。

它不太可能把 GNPR/GHR 等系统性数个百分点损失自动翻转为提升。建议只对最终两三个候选运行完整 Validation，不为每一个静态 SID 候选付出全量评测成本。

此外，当前固定 10k 已被多轮方法比较和超参数选择，事实上已经成为开发集。后续应把方法选择放在 Train 内时间留出或单独 Dev 分区，保留一个与当前 10k 不重叠的 Validation 确认集；Test 继续只在方法、参数和解码全部冻结后读取。

## 5. 为什么三篇论文基线构成较强目标

三篇论文基线承担不同作用：

- **TIGER** 是固定长度语义 SID 和无约束生成的最强结构基线，最适合诊断自研 SID 是否真正更可生成；
- **Centered GenPOI** 是当前普通固定 10k 的完整方法数值最强基线，也是复杂地理 Query 的 Top-K 最强基线；
- **GNPR** 在当前地图适配中整体较低，但代表内容、地理和 Diversity Loss 的另一类论文方法，仍需完整报告，不能因结果较低而从基线集合中删除。

因此，TIGER 仍是解释 SID 机制和做同协议消融时的主要结构对照，但自研方法的最终成功线必须是三篇论文复现的最强结果包络，而不是只超过 TIGER。

### 5.1 TIGER 的结构优势

TIGER 的优势不是“SID 语义一定最好”，而是其标识和训练任务与当前流量分布形成了一个很强的工程平衡：

1. 三层 RQ-VAE 前缀加一个固定 collision token，目标长度稳定为四个代码 Token，序列闭合简单；
2. 第一层在固定 10k 的 gold-prefix Teacher-Forcing Top-1 为 75.06%，根节点具有较强可预测性；
3. 固定 10k 的碰撞桶目标率和 `C>0` 比例分别为 38.54% 和 23.56%，低于多个静态唯一率更好的 E4/RQ-KMeans 候选；
4. 虽然 `C` 只是桶内按 POI ID 排序的无语义编号，但 758 万 Train 请求中的重复 Query、目标频次、历史和流行度允许模型学习稳定统计偏好；
5. 固定长度减少了变长路径、提前 EOS、短路径偏置和关系 Token 长尾支持问题。

因此，新增方法必须同时改善“前缀可预测性、热点碰撞、后缀排序和序列稳定性”中的至少一项，并且不能在其他项付出更大代价。只改善全目录 POI 等权唯一率不足以超过 TIGER 的结构平衡，更不足以超过包含 GenPOI 完整推理链路在内的三篇论文最强包络。

训练硬件不是当前主要解释。相关实验保持模型、BF16、global batch、数据和评测协议一致；A100 与 6000D 不应造成数个百分点的系统性差距。单 seed 可以影响亚百分点排序和 E4 对称布局的闭合异常，但无法解释多个不同方法重复出现的相同方向性问题。

## 6. 主要失败机制

### 6.1 连续向量目标与离散生成目标错位

E4 是最关键的证据：

- BGE E0 的连续精确召回 Hit@10/NDCG@10 为 32.39%/21.2113%；
- E4 最终冻结版本达到 56.37%/36.3976%，分别提高 23.98/15.1863pp；
- E4 + RQ-VAE 相对 TIGER 的生成式 HR@10/NDCG@10 却下降 1.00/1.4850pp。

连续检索直接使用 Query 与 POI 向量的相似度；生成式检索不在推理时访问 POI 向量，而是要求模型从文本输入预测聚类后的人为 Token 编号。只有当 E4 的几何改善同时形成 Query 可预测的稳定簇边界时，收益才可能传递到 SID 生成。

E4 聚合的是每个 POI 的历史 Query 中心。对于高频 POI，该中心可能同时包含品牌、类别、商圈、地址、别名和泛需求，直接向量检索可以利用这种多模态相似度；单一离散路径却必须把这些方向压缩成一个固定标签。聚类优化的重构误差不会自动最小化 `H(SID | Query, GID, History)`。

### 6.2 全目录唯一率与请求加权碰撞反转

全目录静态指标按 2,337,178 个 POI 等权；SFT 检索指标按真实请求目标加权。两种统计口径已经发生明确反转：

| Identifier | 全目录碰撞 POI | 固定 10k 碰撞桶目标 | 固定 10k `C>0` | 固定 10k 平均桶大小 |
|---|---:|---:|---:|---:|
| TIGER `1024³` | 40.7894% | **38.54%** | **23.56%** | **2.5339** |
| E4 RQ-KMeans `1024³` | **35.7477%** | 49.29% | 34.15% | 3.2469 |
| E4 RQ-KMeans `2048×1024×512` | **31.4021%** | 41.90% | 27.50% | 2.6286 |

E4/RQ-KMeans 的静态改善主要发生在 POI 长尾，没有同步消除请求更常命中的热点桶。容量前移能缩小差距，却同时增加第一层分支数和低支持标签，最终形成新的代价。

这说明后续所有 SID 训练前门禁都必须加入请求加权指标，不能再只看 POI 等权唯一率和最大桶。

### 6.3 自回归前缀瓶颈

生成式标识符的早期 Token 一旦错误，后续条件全部改变。GNPR 的逐层诊断最清楚：

- GNPR S1 Top-1 为 53.69%，比 TIGER 的 75.06% 低 21.37pp；
- 给定正确前缀后，GNPR S2/S3 分别比 TIGER高 2.39/6.32pp；
- 完整 identifier Teacher-Forcing 的方法差距与自由生成 HR@1 差距接近。

因此 GNPR 不是“后层码本没有学习”，而是 content/category/PlusCode 融合后的根聚类编号难以由当前 Query 预测。Diversity Loss 提高码本利用率也不能修复这一条件分类问题。

容量前移与后移实验也体现了相同权衡：

- 容量后移减少第一层类别数和低支持分支，但增加后段碰撞与 `C>0`；
- 容量前移降低后段碰撞，却提高 S1 分类数和标签稀疏性；
- 两种代价在端到端结果上基本抵消，继续做更极端的静态容量排列价值有限。

### 6.4 唯一后缀抵消前三层收益

E4 RQ-KMeans 的前三层并不是整体不可学：

| Identifier | S1 | S1+S2 | S1+S2+S3 | 完整四 Token ID |
|---|---:|---:|---:|---:|
| TIGER | 75.06% | 61.75% | 53.98% | **50.76%** |
| E4 RQ-KMeans `1024³` | 80.70% | **66.72%** | **56.83%** | 49.01% |
| E4 RQ-KMeans `2048×1024×512` | **82.25%** | 65.08% | **55.97%** | 49.91% |

前三层累计准确率高于 TIGER，但 `C>0` 的 collision token Top-1 从 TIGER 的 81.03% 降到 73.65%/74.33%，同时新方法拥有更多 `C>0` 请求。最终收益被无语义的桶内唯一编号抵消。

E4 对称布局还出现独立的闭合异常：`</TARGET_POI>` gold-prefix Top-1 只有 94.19%，自由生成产生 9,202 个 missing-EOS 候选。合法路径约束消除了该异常的大部分影响，但仍没有获得 Top-1/NDCG 的整体领先。这说明闭合异常放大了负结果，却不是全部原因。

### 6.5 静态关系可区分，但请求未必表达

QGR 的离线代理已经给出边界：

- full lexical relation 相对桶内流行度 HR@1 提高 1.7405pp；
- Query 引导相对静态关系只多命中 67 条；
- 完整关系路径在 holdout Query 中精确表达的请求只有 5.0964%；
- 可靠关系版本仍有 92.7715% 的 early 碰撞请求必须回退 TIGER，只保留 full lexical 82.47% 的增量，未通过预注册门禁。

GHR 把关系直接作为 Query-free 静态目标后，暴露出更明显的生成成本：

- EXP-09 固定 10k 平均逻辑长度为 3.8689；
- EXP-14 增至 4.1466，且存在 7—16 的长尾；
- 关系 Token 越多，越需要 Query 准确表达楼栋、单元、门牌和层级；
- 合法路径约束在变长 Trie 中表现出明显短路径偏置，合法并不等于正确。

所以关系本身有信息价值，但更适合做辅助监督、候选排序或 Query 明确表达时的软特征，不适合无条件成为每个 POI 必须生成的硬路径。

### 6.6 精确 POI ID 中存在不可学习信息

GHR 残留审计在 75,427 个难区分 POI 中发现：

- 20,347 组、43,718 个 POI 的名称、地址、别名、分类、精确坐标等稳定字段全部相同；
- 原始字段不归一化复核后结论几乎不变；
- 完全重复组中酒店约占组数 94.50%、POI 数 94.58%。

如果模型输入和候选特征无法区分这些记录，预测具体原始 `poi_id` 就包含不可观测标签。无语义 `C/D` 只能学习流行度或数据源偏好；继续补更多静态关系无法解决完全重复实体。

后续必须同时保留两种口径：

1. 精确 POI ID 指标，继续反映当前业务标签；
2. canonical/equivalent POI 指标，区分“检索到等价实体”和“命中任意数据源行”。

如果业务确认这些记录确实等价，训练可以使用多正例或 canonical target；如果业务必须保留每个原始 ID，就必须提供能够区分它们的真实业务字段，否则不能把该部分误差归因于模型能力。

### 6.7 Token 级训练目标与 POI 排序目标不一致

当前 SFT 使用逐 Token 交叉熵。该目标具有以下局限：

- 变长目标的长路径贡献更多 Token；
- EOS、闭合符和关系 Token 的损失不等价于最终 POI 排名损失；
- 同一个碰撞桶内的难负例没有被显式比较；
- Validation Loss 可以下降，但 Beam 内目标排名仍可能变差。

GHR EXP-14 的 Validation Loss 低于 EXP-09，但 HR/NDCG 更差，已经证明不能用 Token 平均 Loss 代替检索指标。后续需要在固定长度生成之外增加桶内 listwise、pairwise 或候选蒸馏目标。

## 7. 各创新方向的保留与停止判断

| 方向 | 已得到的正向证据 | 当前主要问题 | 决策建议 |
|---|---|---|---|

| RQ-KMeans | 静态唯一率提升；BGE + RQ-KMeans 与 TIGER 基本持平 | 量化器不是主要瓶颈，收益低于统计分辨率 | 保留为稳定量化器对照，不继续增加静态 `2×2` 或容量矩阵 |
| 容量前移/后移 | 定量揭示首层难度与后缀碰撞的权衡 | 两种代价几乎抵消 | 停止更极端容量搜索，除非新的 Query 可预测目标改变该权衡 |

## 8. 推荐的下一阶段路线

### 8.1 P0：先修正评测与标签契约

在启动新的完整 SFT 前，建议先完成以下冻结：

1. 将当前固定 10k 明确定位为通用流量回归 Dev；
2. 已从 Validation 冻结四个彼此互斥且排除随机/地理参考集的新专项集：已见 Query/未见 Query–POI、新 Query/已见目标、长尾 POI 和冷 POI，每组 10k；
3. 已有复杂地理 Query 10k 继续作为独立参考；碰撞/重复实体仍需在 exact 指标之外补充 canonical/equivalent 口径；
4. 新增生成评测保存逐样本 target rank、生成的基础 SID 桶、完整候选和错误类型，支持 paired bootstrap；当前 TIGER 普通 10k 已完成，其他方法仍待按同一 schema 补齐；
5. 同时报告 exact POI 与 canonical/equivalent POI 指标；
6. 只有候选冻结后才运行完整 Validation，Test 保持最终一次读取。

该阶段不是为了“换一套更容易的数据”，而是区分通用流量、目标专项增量和不可观测标签，避免继续用一个总指标掩盖不同问题。

### 8.2 P1：优先做基础 SID 桶召回与展开重排诊断

这是当前成本最低、决定性最强的下一项建议，不需要重新训练大模型。

对现有 TIGER、BGE + RQ-KMeans 和必要的 E4 候选：

1. 将生成候选折叠到前三层基础 SID，去掉第四层 `C`；
2. 统计目标基础桶的 `Bucket-HR@1/3/5/10`；
3. 展开命中桶内全部 POI；
4. 依次使用以下 Train-only/静态信号重排：
   - E4 Query–POI 连续相似度；
   - 请求 GID 与 POI 坐标距离；
   - 历史 POI、品牌和类别相关性；
   - Train-only 热度与时间衰减；
   - GHR 已抽取的楼栋、单元、门牌和父子关系；
5. 报告桶召回、桶内目标排名、最终 exact/canonical HR/NDCG 和不同桶大小分组。

可先用一个可解释线性打分：

\[
s(q,i)=w_{sem}s_{E4}(q,i)+w_{geo}f_{dist}(q,i)+w_{hist}f_{hist}(q,i)+w_{pop}\log(1+c_i)+w_{rel}f_{rel}(q,i)
\]

权重必须在 Train 内时间留出上拟合或选择，不能继续用固定 10k 调参。

该诊断形成清晰决策：

- Bucket Recall 高、重排后超过三篇论文最强包络：主要瓶颈是 `C/D` 后缀，应转向桶内条件排序；若只超过 TIGER、未超过 GenPOI，则只能说明 SID 结构得到改善，尚不能认定完整创新成立；
- Bucket Recall 低：主要瓶颈仍在前三层 Query→SID，需要继续 QD-RQ；
- canonical 指标明显高于 exact 指标：重复目录标签是主要误差源，应先处理等价实体；
- E4 重排有效但 E4 SID 无效：进一步确认连续信息应作为打分/蒸馏信号，而不是直接通过静态重聚类传递。

这一方向与《方案.md》已经定义的“SID 碰撞后展开 POI 集合，并结合距离、历史、热度等排序”一致，不是额外扩大项目范围。

#### 当前进度（2026-08-19）

`EXP-20260819-01/02/03` 已完成 TIGER 与五个创新候选的同口径诊断，并补齐容量前移：

| 口径 | HR@1 | HR@3 | HR@5 | HR@10 |
|---|---:|---:|---:|---:|
| 精确四层 ID→POI | 51.87% | 76.00% | 82.26% | 87.16% |
| 三层唯一可展开 Bucket | 55.53% | 79.64% | 85.10% | 88.06% |
| E4+RQ-KMeans 容量后移：精确四层 | 50.58% | 75.56% | 82.07% | 87.07% |
| E4+RQ-KMeans 容量后移：三层唯一 Bucket | **59.69%** | **81.55%** | **86.53%** | **88.45%** |

| E4+RQ-KMeans 容量前移：三层唯一 Bucket | 57.38% | 80.23% | 85.33% | 87.74% |

- 目标 Bucket 在 Top-10 缺失 1,194 条，精确 POI 缺失 1,284 条；所以在现有 Beam 内，即使桶展开和桶内排序完美，Top-10 最多新增 90 条命中。
- 目标桶 61.46% 为单例、38.54% 为碰撞桶，平均大小 2.5339、最大 172；每条请求平均只有 6.5462 个唯一可展开候选桶。

- 结果否定“只要去掉第四层就能大幅补回 Top-10”，但支持“更易预测的粗桶能够改善前排覆盖，再用条件排序解决桶内实体”。P1 因而进入冻结容量后移候选的 E4 连续相似度轻量重排，不启动新 SFT；若该无标签重排门禁失败，再执行 P2 的 QD-RQ Top-32 弱权重门禁。

### 8.3 P2：只保留受限 Query-Predictable RQ 作为 SID 主线

现有 QD-RQ 强权重 R3 在固定 100,000 样本上：

- S2 assignment 变化 18.213%；
- S3 assignment 变化 32.046%；
- Query residual MSE 按设计下降；
- distinct SID ratio 从 96.686% 降到 93.016%；
- 最大样本桶从 13 增到 27。

它证明 Query 信号能够进入中后层，也证明不受限的全局 reassignment 会破坏内容结构。建议的唯一下一候选是：

- S1 冻结；
- S2/S3 assignment 只允许在内容距离 Top-32 候选内移动；
- Query 权重使用 `λ=[0,0.05,0.15]`；
- 无 Query 覆盖 POI 保持 content-only；
- 使用 Train 内时间切分评估未来 Query→SID，而不是只比较聚类训练样本；
- 以请求加权 conditional accuracy/entropy 和热点碰撞为主门禁。

除现有静态门禁外，建议在运行前预注册新增门禁：

1. 样本 distinct SID ratio 相对对照下降不超过 0.5pp；
2. 样本最大桶不超过对照 1.25 倍；
3. D2/D3 micro-purity 分别下降不超过 0.3/0.5pp；
4. 请求加权碰撞桶目标率和 `C>0` 比例不得同时劣于 TIGER；该项是 SID 结构门禁，不替代最终超过三篇论文包络的验收；
5. 轻量 Query→逐层 SID probe 的三级累计准确率必须获得超过统计噪声的正向提升；
6. 只有固定样本和全量编码两层门禁都通过，才构建 SFT 数据并运行一次同协议完整训练。

后续 SID 目标可概念化为：

\[
L_{SID}=L_{content}+\sum_l\lambda_l L_{query\rightarrow code}^{(l)}
 +\mu L_{traffic\ collision}+\nu L_{stability}
\]

其中 `L_query→code` 应来自请求级 Query 预测或对比学习，而不是仅让每个 POI 的聚合 Query 中心靠近码本；`L_traffic collision` 必须按真实请求权重计算。

### 8.4 P3：主方法转向“生成语义桶 + 局部条件指针/排序”

如果 P1 证明基础桶召回足够高，最值得形成完整方法的结构是：

```text
Query + GID + History
          ↓
生成固定长度三层语义 Bucket
          ↓
展开一个或多个 Bucket 中的 POI
          ↓
Query / 地理 / 历史 / 热度 / 关系联合打分
          ↓
输出最终 Top-K POI
```

具体原则：

1. 保留固定长度可学习前缀，不再生成长关系树；
2. 将第四层无语义 `C` 替换为桶内局部 pointer/listwise 排序，或只把 `C` 保留为兼容对照；
3. 关系和细地理作为候选特征或辅助任务，不再无条件进入目标序列；
4. 在同一桶内显式采样难负例，使训练目标直接区分同名、同类、邻近 POI；
5. 对完全重复实体使用 multi-positive/equivalence-aware loss，业务仍需精确 ID 时再按稳定规则展开；
6. 首版先冻结生成模型，只训练轻量桶内排序器，验证有提升后再考虑联合训练。

这一结构直接对应当前三个最主要的问题：

- 保留 E4 连续相似度收益；
- 避免要求 Query 生成不可观测的 `C/D`；
- 把地图特有的距离、历史、热度和实体关系放到真正影响排序的位置。

### 8.5 P4：通过软监督或联合目标把检索信号传给生成器

只有 P1/P3 已验证桶内排序收益后，才值得推进更复杂的统一训练。候选包括：

1. 使用 E4 或桶内排序器分数，为 Trie 每个 Prefix 下的合法子节点构造软目标；
2. 在 one-hot gold token 之外，让同一等价实体或高相关候选共享部分概率质量；
3. 增加同桶 listwise loss，使生成 hidden state 能区分目标和桶内难负例；
4. 逐层蒸馏 Query→Bucket 的概率，而不是仅蒸馏最终 POI；
5. 最终联合目标可写为：

\[
L=L_{token}+\gamma L_{bucket\ listwise}+\eta L_{geo/history}+\kappa L_{equivalence}
\]

该阶段复杂度较高，不应在基础桶召回和轻量重排尚未验证前直接实现。

## 9. 建议形成的创新主张

如果后续门禁和端到端实验通过，可以把当前分散的工作收敛为三个相互配合、面向地图 POI 的候选贡献点：

### 9.1 请求加权、Query 可预测的分层标识符

不再以全目录唯一率作为唯一目标，而是联合内容局部稳定性、真实请求权重、逐层 Query 可预测性和热点碰撞风险。重点是“可由请求生成”，而不只是“可由 POI 重构”。

### 9.2 语义桶生成与地理行为条件消歧

生成模型负责语义候选覆盖，局部排序器负责同桶实体消歧。Query、请求位置、用户历史、POI 热度和数值关系在候选层联合建模，避免把所有信息硬编码成一条静态 SID。

### 9.3 重复实体感知的训练与评测

显式识别地图目录中静态字段不可区分的重复 POI，联合报告 exact 与 canonical 指标，并使用多正例或等价类监督减少不可学习标签噪声。这是地图 POI 相比普通商品推荐更突出的数据问题。

这三个方向可以形成一条完整逻辑：

> 静态语义 SID 不能保证请求可生成，因此先学习请求可预测的语义桶；地图中的精细实体和重复记录再通过地理、行为和等价感知的局部排序解决。

## 10. 不建议继续投入的实验

在没有新条件信号或新训练目标前，不建议继续：

1. 增加更多 `256/512/1024/2048/4096` 静态容量排列；
2. 仅以全目录唯一率、类别纯度或最大桶选择下一次 SFT；
3. 把更多楼栋、门牌、细 GID、alias 或地址字符继续追加为必须生成的变长关系 Token；
4. 对未通过 Train 时间留出代理门禁的 SID 候选直接运行三轮全量 SFT；
5. 在同一个固定 10k 上继续反复调 E4 权重、关系阈值、重排权重或解码超参数；
6. 用 GPU 型号差异解释已经跨多个方法重复出现的数个百分点下降；
7. 只报告合法率或 Validation Loss，而不报告请求加权碰撞、逐层条件准确率和最终 POI 排名。

## 11. 下一步决策顺序

当前建议顺序不是直接开始新的完整训练，而是：

1. **继续完成 P0/P1。**评测分组和 TIGER 基础桶召回已冻结；下一步补 BGE+RQ-KMeans/E4 的同口径 Bucket-HR，再决定是否值得做展开重排，exact/canonical 差距仍待测；
2. **根据 P1 结果选主线。**桶召回高则优先局部排序，桶召回低则优先受限 QD-RQ；
3. **QD-RQ 只跑 Top-32 弱权重固定样本门禁。**未通过就停止聚类重构，不进入 500k/全量/SFT；
4. **局部排序先冻结 TIGER 前缀。**只训练轻量排序器，先验证是否超过 TIGER 的完整 `C` 生成，再判断能否超过 Centered GenPOI 和三篇论文最强包络；前者是机制验证，后者才是完整创新验收；
5. **只有一个模块得到稳定增量后才做联合训练。**避免同时改变 Embedding、Quantizer、标识长度、解码器和排序目标后无法归因；
6. **最终候选再做完整 Validation、第二 seed 和 Test。**亚百分点差异必须用配对置信区间确认。

## 12. 当前尚未回答的问题

1. 容量后移的前三层 Bucket 前排覆盖已经显著高于 TIGER，但 HR@10 只高 0.39pp 且区间跨 0；这一结构收益能否转化为最终 POI HR/NDCG；
2. 去掉 `C` 后，E4 连续相似度能否在生成桶内和跨桶候选中恢复其直接检索收益；
3. exact 与 canonical 指标之间有多大差距，重复实体实际影响多少固定流量；
4. 当前 10k 上 BGE + RQ-KMeans 与 TIGER 的亚百分点差异是否通过 paired bootstrap；
5. QD-RQ Top-32 弱权重能否在不破坏结构的情况下提高请求级逐层可预测性；
6. GenPOI 的复杂地理收益分别来自 SSP、TCG、地理前缀还是它们的交互；
7. 北京单城结果能否外推到多城和跨城 Query，目前没有证据支持直接外推。

这些问题的优先级以“能否改变下一次完整 SFT 决策”为准，而不是以实现复杂度或静态指标是否好看为准。
