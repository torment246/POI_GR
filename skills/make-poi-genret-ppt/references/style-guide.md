# 0727/0810 PPT 样式与交付规范

## 1. 权威顺序

1. 用户本轮提供的最新 PPTX/PDF：内容和页序权威。
2. `胡丹-0810.pptx`：最终确认过的视觉密度、表格表达和少装饰原则。
3. `胡丹-0727.pptx`：原始模板、标题体系和基础版式来源。

用户本轮明确要求优先于历史模板。本规范的更新规则为：大标题统一黑色、实验结果使用表格、方法说明按流程或结构展示。除此之外沿用 0810 的视觉密度和少装饰原则；不要因为旧模板存在较多 AutoShape，就恢复装饰性卡片阵列。

## 2. 版面基线

- 页面：16:9，13.333 × 7.5 英寸。
- 背景：白色或模板已有的极浅底色。
- 主字体：`微软雅黑` / `Microsoft YaHei`。
- 常用字号：页标题约 28 pt，正文和表格约 16 pt；副标题可沿用相邻模板页的 20 pt。优先复制已有页面，不凭空重新设字号。
- 页标题、章节编号、页脚和内容区边界必须与相邻模板页对齐。
- 保留充分留白；信息多时拆页，不用方框堆叠内容。

## 3. 颜色

优先复用现有主题色，不扩展调色板：

| 用途 | 颜色 |
|---|---|
| 所有大标题（含封面、章节、页标题） | `#000000`，显式设置 |
| 正文深色 | `#111827` |
| 次级重点文字、表头文字 | `#1A3A6B`（不得用于大标题） |
| 次要文字 | `#64748B` |
| 表头底色 | `#E2E8F0` |
| 隔行底色 | `#F8FAFC` / `#FFFFFF` |
| 单一重点行 | `#EAF2FF` 或 `#EBF4FF` |
| 必要浅边线 | `#CBD5E1` |
| 反白文字 | `#FFFFFF` |

不要为了区分实验组而各设一种高饱和颜色。结果通过表格行名、粗体和单一浅蓝选中行区分；方法通过流程分支标签和布局区分。黑色大标题并不意味着给流程节点加黑色描边。

## 4. 表格

- 实验结果、数据集统计、配置映射和需要逐项精确对照的指标优先用表格。
- 方法步骤、模块关系、数据流和训练阶段不使用整页说明表；按下节规则展示。方法的精确配置对照可以使用小表，但不能用它替代主流程。
- 表头使用安静的灰色底；正文白色/极浅灰隔行；最佳或冻结项最多使用一行浅蓝高亮。
- 数值列保持统一小数位、百分号和 `pp` 口径；同一页不要混用 0.7 与 70%。
- 指标很多时缩短列名或拆表，避免把字号压得过小。
- 表格之外只保留一段结论或少量解释，不再为每个结论加独立卡片。
- 不使用粗黑外框。边线若需要，只使用模板已有的浅灰细线。

## 5. 方法与流程

- 先确定信息类型：顺序处理用流程，模块交互用架构图，阶段进展用时间线，简单结论用简洁分段文字。不是所有页面都需要表格，也不是所有页面都需要方框。
- 方法页优先呈现“输入—关键处理—输出”；并行视图用分支，融合用汇合，交替优化用带标签的回路。训练与推理、已完成与计划中必须区分。
- 使用 PowerPoint 原生可编辑文本、形状和连接线；不能只把表格行换成互不连接的卡片。
- 功能节点可用白色或极浅灰底、浅灰细线；只在确有数据流、时序或依赖时使用箭头。连接线不得穿过文本或无意义交叉。
- 每个节点保留短名称和必要说明，正文约 16 pt。长公式、规则和限制放在图下少量解释或拆页，不把大段说明塞进节点。
- 沿用模板的留白、字体、标题位置和页脚；不要给整幅流程再加一个装饰性外框。

## 6. 禁止的视觉元素

- 不使用大面积彩色卡片、多列卡片阵列或每段一个矩形容器。
- 不使用黑色描边矩形、空心小方框、彩色徽章、阴影、渐变或装饰性分隔框。
- 不使用 emoji、Dingbat、图标字体或 `□ ■ ▪ ▣ ☑ ✅ ❌` 等字符作为项目符号。
- 不使用可能因字体缺失显示为黑线小方框的罕见 Unicode 字符。
- 不为抽象结论强行增加流程，也不因“少装饰”而把真实方法流程改成文字表格。
- 不添加与结论无关的插图、背景纹理和颜色。

## 7. 内容组织

- 每页只回答一个问题：做了什么、结果如何、为什么、下一步是什么。
- 结果页先给表格，再给一句可验证的结论。
- 方法页先给主流程或结构，再给关键机制与边界；进展页用阶段路线或简洁文字，避免整份汇报千篇一律的表格。
- 复现结果与创新实验分段；结构指标、Teacher-Forcing、最终生成召回不可混作同一指标。
- 成功、失败、中止分开表述。平台显示 failed 时必须核对错误发生在 Trainer 前还是保存后。
- 写清口径：固定 10k Validation、Beam、约束解码、是否使用 Trie、是否完成 Test。
- 不把“唯一率更高”“Valid ID 更高”直接写成“召回更好”。

## 8. 备注

- 默认不创建、补写或修改备注。信息过多时优先精简正文或拆页，不把备注作为常规交付内容。
- 只有用户在当前任务中明确要求备注时，才使用备注补充正文没有空间承载的内容，例如：

  - 方法公式或实现细节；
  - 复现适配与原论文的差异；
  - 失败实验的现象、原因、排查证据和解决方式；
  - 指标定义及不能比较的边界；
  - 数据泄漏检查、固定子集和运行环境；
  - 汇报时的转场逻辑。

不要逐句复述页面文字。备注应让汇报人能够回答追问，而不是形成第二份正文。

## 9. 修改与验收

- 新建：以 0810 或 0727 的近似页面为模板复制，保留 master/theme。
- 增页：页面编号、标题位置、表格样式和留白必须与前后页一致。
- 仅备注：正文 XML 的 canonical hash、shape 数量、文本和表格必须保持一致。
- 交付前逐页检查：所有大标题均为 `#000000`；结果表格与方法流程各司其职；箭头方向清楚；无溢出、无重叠、无装饰性黑色方框、无乱码方块、无突兀颜色、无过密文本。
- PPTX 必须能重新加载，ZIP 检查无损坏；有条件时再导出 PDF 做视觉核验。
