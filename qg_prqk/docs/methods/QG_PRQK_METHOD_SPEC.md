### 0.1 开发前复核与迭代原则

保留全量 Query、软粒度、POI 搜索分布和共享 assignment 的主方向；本版是待检验的工作假设，不是必须逐项兑现的固定功能清单。2026-09-19 复核修正如下：

| 发现 | 修正 | 位置 |
|---|---|---|
| 用最大深度概率作质量权重，会对粒度不确定性重复降权，连确定可用的 S1 也被削弱 | 深度概率只负责路由，质量单独定义；合法关系首轮质量为 1 | 第 3 节 |
| 在分层后对证据量截断，许多浅 Query 的微小 S3 概率会累积成完整 S3 权重 | POI 总量先归一化，再乘深度 gate，保留平均可监督深度 | 第 4 节 |
| 零条件残差到不同 V 的距离仍不同，与“只利用父组内剩余差异”的意图不符 | 无剩余差异的行关闭搜索项，并统计其覆盖 | 第 5 节 |
| 旧 S3 的内容 Top-32 候选与新联合全码分配不同 | 新配对两边统一全 512 候选；旧 A0/A4 仅作历史参照 | 第 5、9 节 |
| 新 D1/D2 含义已改变，旧类别集中度不能直接生成新深度真值 | 文本、目录歧义与人工样例共同定标签；类别统计仅辅助 | 第 3 节 |

上述公式已做 10 项 CPU 合成数学检查，包括浅层不被重复降权、深层权重不被累积放大、权重上限/单调性、零证据、父组中心化、零残差中立及共享成员的搜索质心更新。它们不是 v3 生产实现测试，也不能证明检索收益。

开发遵循“先复用、先形成可比较实验、最后整理代码”。允许依据 Validation 和真实 Qwen 结果修改路由、分布、中心化或损失；每次只改变可归因的因素，记录实际配置和负结果。代码复用方式、实施切片及结果驱动的调整表见[执行计划](QG_PRQK_CODEX_EXECUTION_PLAN.md#v30-当前执行导航2026-09-19)。

## 1. 为什么迭代，以及具体改进什么

### 1.1 已有证据与解释边界

- A0 是 POI-only Projection-Residual KMeans，配合相同 GID/Dedup、Qwen SFT 和解码协议；A4 增加 Query、类别和局部地理组件。全量 Test 约束 A4−A0 的 HR@1/HR@10/NDCG@10 为 `+0.0125/−0.0157/+0.0183pp`，尚无清晰的组合净收益。见 [EXP-20260918-02](../experiments/QG_PRQK.md#exp-20260918-02a0-gid-全量-test-双解码验收)。
- 现有 S1/S2 图加权一致率约为 `81.68%/80.28%`，但 S2 Query distortion 从 A0 的 `0.592466` 变为 `0.620627`；受控诊断将主要静态代价定位到 coupled assignment。类别纯度仍有改善，因此类别暂不重做。详见[实验台账](../experiments/QG_PRQK.md)。
- 五组各 100 条 Qwen 配对诊断中，A0/A4 三层同时 Top-1 正确率均为 `43.4%`；静态 probe 差距没有等幅传递到 Qwen。上述结果支持改造监督机制，不能证明某个模块是最终指标不升的唯一原因。

v3.0 保留研究问题：**POI 的编码同时表达“它是什么”和“用户为什么搜索它”，不同粒度的真实搜索需求影响不同层级。** 下文改进均为待验证假设，不预写收益。

### 1.2 v2.1-CAT 与 v3.0 的机制对照

| 环节 | 当前 v2.1-CAT 实现 | v3.0 设计 | 要解决的问题 |
|---|---|---|---|
| Query 覆盖 | 1,372,661 个 Query 中 342,879 个进入 SID 图；D0 排除 | 保留全部合法 Query–POI 对，输出全量软路由及实际有效权重覆盖 | 避免将低支持 Query 与无可用语义混为一类 |
| 粒度来源 | 目标/粗细类别的集中度、熵、阈值，D0–D3 硬分层 | 文本粒度模型，日志弱标签与小规模人工纠偏，输出 D1–D3 概率 | 单次命中不能证明精确；类别集中不等于搜索表达具体 |
| 粒度语义 | D1=粗类别，D2=细类别，D3=Exact-core | D1=宽搜索需求，D2=带限定的集合，D3=具体实体/入口 | 将类别属性与 Query 能提供的区分强度分开 |
| 可靠性 | 与支持量、集中度、熵共同决定筛选及边权 | 深度概率、证据可靠性、POI 入边总量分别记录 | 低频精确 Query 可参与，热门 POI 不支配目标 |
| Query 表示 | D1/D2 Raw BGE，D3 Exact Adapter | 首轮统一使用冻结 Raw BGE 的固定语义参照分布 | 不将 Exact-only Adapter 外推到全部泛搜 Query |
| 搜索视图归属 | Query 是独立节点，有自己的离散 assignment | 搜索分布属于 POI；Query 只提供冻结语义证据 | 减少 Query 改换 code 就提高一致率的途径 |
| 双质心 | POI 和 Query 各自分配，图鼓励同码 | 每个 POI 一套分配，内容/搜索两个质心共享这套成员 | Query 必须通过 POI 分配和质心更新改变 SID |
| 搜索结构 | 单个 Query 向量；直接均值扩展仍只有一阶统计 | 在固定 Query 参照点上保留各 POI 的搜索分布 | 尽量保留多种搜索表达，降低均值混合造成的信息损失 |
| 层级关系 | 两套独立 assignment 及各自投影残差 | POI 内容沿原 PRQ 残差；搜索视图沿同一 POI 前缀做条件中心化 | 深层表达父组内差异，避免两套路径不一致 |
| 类别 | S1 粗类、S2 条件细类软代价 | 首轮保留 | 保护全目录语义组织与无 Query POI |
| 地理 | S3 局部 Geo 特征及同码困难边惩罚 | `v3-query` 保留算法；`v3-geo` 后续只惩罚远距离同码冲突 | 单独检验过度实体区分，不与 Query 改动混在一起 |
| 验收 | 已有静态指标与真实 SFT 结果 | 真实 Qwen SFT、完整 POI 指标及配对差异作为最终判据 | 避免用聚类指标替代生成能力 |

当前 BGE/Adapter 向量已经冻结。v2.1 的问题假设针对 `_assign_query` 的自由离散分配及后续 Query 质心更新，不能描述成“旧版在用 SID 反向训练 BGE”。

## 2. 数据流、输入和冻结边界

### 2.1 数据流

```text
Train Query–POI 全量统计 ──> 弱标签 + Train 内人工纠偏/校准
        │                         └─> Query 粒度概率、可靠性
        ├─> 全量 Raw BGE Query ──> 冻结语义参照点、Query 软分布
        │                                      │
        └─> 全部合法正向关系 ────────────────────┘
                    └─> 每个 POI 的三层搜索分布、证据总量
                                   │
active POI BGE ──> 内容 PRQ 残差 ────┼─> 一套 POI assignment
全目录类别 ──> S1/S2 软代价 ─────────┘       ├─> 内容质心 U
                                            └─> 搜索质心 V
                冻结 S1，再构造 S2 搜索残差；冻结 S1/S2，再构造 S3
                                   └─> S3 地理项
                                        └─> GID6 + SID3 + 条件 Dedup
                                             └─> 同协议 Qwen SFT
                                                  └─> 固定 10k + 四个泛化集
```

该流程描述数据依赖，不代表已生成产物。首轮只选 GID 分支，NoGID、PID 顺序、容量和训练模型不同时扩展。

### 2.3 数据隔离与版本隔离

- Query 统计、粒度标签/训练/校准、语义参照点、搜索分布和 SID 构建只读取 Train 及冻结 POI 属性。业务 Validation 用于下游 SFT/生成候选选择；Test 不参与选参。
- 粒度模型使用 Train 内按归一化 Query 分组的独立训练、校准、验收切分；同 Query 的不同订单不能跨组制造泛化假象。内部验收集不参与该阶段模型或校准器拟合。
- active 目录成员资格沿用既有闭集协议，不等同于允许读取 Validation/Test 的 Query 或订单标签。
- 首轮不扩展日志时间窗口，不重新编码 POI，不修改 GID，不做 RQ-VAE、RL、动态 SID 或新增生成模型。
- 新配置、schema 和输出单独版本化。拟定输出前缀 `qg_prqk/outputs/qg_prqk_v3_0/` 尚未创建；现有 v2.1 校验器应继续拒绝来源不匹配，不能改签名混用新旧产物。

## 3. 软粒度模型：学习可监督深度，单独处理可靠性

### 3.1 标签定义与路由

| 标签 | 定义 | 示意 | 作用 |
|---|---|---|---|
| D1 | 宽搜索需求 | 医院、咖啡店 | S1 |
| D2 | 带类型、属性、品牌或范围限定的集合 | 儿童专科医院、24 小时咖啡店 | S1、S2 |
| D3 | 足以指向具体实体或入口 | 明确的店名加分店名、楼栋入口 | S1、S2、S3 |

这些是需结合目录歧义校验的标注示意，不是关键词硬规则。粒度表示适合施加的语义区分强度，不规定最终生成长度，也不等于 `category_code` 的层数。短名称可能精确，长属性描述仍可能对应多个 POI；无法判断时记录未知或部分标签，不把未知标成 D1。

首轮模型为冻结 BGE Query 表示加小型分类头，输出 `p1,p2,p3`，满足非负且和为 1。随后计算：

```text
g1 = 1
g2 = p2 + p3
g3 = p3
1 = g1 >= g2 >= g3 >= 0
```

另存 `rho_query` 表示独立的证据质量，必须有限且在 `[0,1]` 内，不能用 `max(p1,p2,p3)` 或深度熵代替。首轮合法、有可用语义的真实关系取 `rho=1`，只有明确无语义/噪声取零并记录理由；不因旧 D0、低频或粒度不确定而置零。首轮不另训练质量模型，未来有独立、经校准的质量证据再引入连续权重。

例如 `p=(0.5,0,0.5)` 表示不确定应止于 S1 还是进入 S3，`g1=1` 仍然成立；再乘 `max(p)=0.5` 会无依据地削弱 S1。标注的 `label_confidence` 只用于粒度头的监督权重，不直接当作 Query–POI 关系质量。深度校准误差与分频次表现仍需独立报告。

### 3.2 标签来源与训练

1. 复用 P2、目录名称/别名/地址和类别统计生成待审弱标签或部分标签；先根据 Query 文本与目录歧义确认可支持的深度。类别集中不能单独作为 `D>=2` 的依据，例如“咖啡店”可能高度集中于细类别但仍是 D1；旧 D3、单目标命中也不直接复制为新真值。
2. 从 Train 分层抽取人工样例，覆盖频次、旧 D0–D3、单目标、品牌、门址、泛搜与上下文表达。先用小批样例核对定义，约 1,000 条是分批扩充的初始规划，不能当作已存在的标签或全部代码开工的前置条件。真实标签分别用于纠偏训练、校准与独立验收，导出具体样本 ID 和标注版本；没有真值时不声称分类头已验收。
3. 若采用跨时间稳定性证据，需额外流式聚合 Train 的日统计。P2 当前没有日维度字段，不得声称已有该产物；首个数据契约闭环不要求重扫全量订单。
4. 完整标签使用分类损失；部分标签可用允许深度集合 `A_q` 的损失 `-log(sum_{d in A_q} p_d)`，仅有下界证据时不能把它解释为精确深度。未知样本不伪造粒度标签，仍可进入后续 Query 表示与软预测。
5. 类别采样/损失避免 D3 弱标签数量支配；记录弱标签来源、人工修订和各类覆盖。先验证小分类头，若关键文本区分不足再考虑编码器微调，不在首轮增加独立意图模型。
6. 粒度模型、校准器与参照表示在 SID 训练前冻结；不使用正在变化的 SID 作为训练标签，也不让量化损失更新该模型。

验收包括宏平均分类指标、D1/D2 被误送入深层的比例、分频次校准误差、人工集一致性与 Query 分组泛化。正确率与允许深层监督的阈值必须在真实标签验收时登记，本文不预设已经达到某个精度。

### 3.3 拟定产物契约

下列为新 schema 的拟定字段，尚无对应文件：

| 产物 | 关键字段/内容 |
|---|---|
| 标注表 | `query_id, allowed_depths, label_source, label_confidence, quality_flag, split, annotation_version` |
| 路由表 | `query_id, p_depth_1, p_depth_2, p_depth_3, gate_s1, gate_s2, gate_s3, rho_query, quality_flag, model_signature` |
| 模型 manifest | BGE/归一化/标签哈希、分组切分、训练参数、checkpoint、校准方法、真实验收指标 |

所有概率必须有限；路由单调；每个全量 Query 恰有一条结果。质量拒绝、缺失、未知和预测分布应分别计数。

## 4. POI 搜索分布：从真实关系构造固定证据

### 4.1 固定 Query 语义参照

在 Train Query 的统一 Raw BGE 空间中，拟合 M 个语义参照点，随后冻结。每个 Query 对最近的少数参照点做 softmax，得到稀疏分布 `phi(q)`。参照点无须命名，也不与 SID code index 一一对应。

- 已核验 `query_embeddings.py::iter_normalized_queries` 按 P2 `query_id` 枚举全部 Query，不按 `is_high_confidence` 筛选；直接复用迭代器与编码器，不新增同功能入口。该代码能力不代表全量缓存已经完成。已有 Raw cache 仅在 Query ID、模型、归一化、截断和行映射一致时复用，补齐缺失行；Exact-core cache 的行号不能当成全量行号。
- 首轮用同一 Raw BGE 空间，不混入 Exact-only Adapter 输出。POI 拟合公共方向如用于 Query，也必须统一应用并记录；不能混用原始和变换后缓存。
- 参照拟合以 Query 类型控制采样，避免复制热门订单形成主导。采样范围、seed、M、soft top-k 和温度进入新配置与 manifest。
- Query 编码和参照软分布各计算一次，按分片存储。不能构造全量 `Query × POI` 相似度矩阵或把七百多万重复订单逐条编码。

### 4.2 边权、分布和证据质量分开保存

首轮可实现的频次压缩与 Query 内归一化为：

```text
f_qp = log(1 + pair_count_qp)
w_qp = f_qp / sum_{p' in positives(q)} f_qp'
c_qp = w_qp * rho_query(q)
M_p = sum_q c_qp
cbar_qp = c_qp / max(1, M_p)
a_qp,l = cbar_qp * g_l(q)
m_p,l = sum_q c_qp * g_l(q)                # 未做 POI 总量缩放的分层证据
b_p,l = sum_q a_qp,l                      # = m_p,l / max(1, M_p)
h_p,l = sum_q a_qp,l * phi(q) / b_p,l      # 仅在 b_p,l > 0 时定义
```

先按 POI 总量缩放、再做深度路由，得到 `0 <= b3 <= b2 <= b1 <= 1`；每个 Query 的每层总贡献也不超过 1。若一个 POI 收到 200 个 Query，每个 `c=1,g3=0.01`，修订前 `min(1,sum(c*g3))=1`，修订后 `b3=0.01`，不会因浅 Query 数量多而获得完整深层权重。共同缩放不改变该 POI 的 `h`，只修正监督强度。

`h` 表示搜索组成；原始 `M/m` 与实际损失权重 `b` 分开保存，归一化后不得丢弃它们。一条独立质量仅为 0.05 的证据仍有 `b1=0.05`。这些是 v3 新公式，不改写旧 P2 的 `sid_weight`。

Query 内归一化是一项明确的频次偏置选择：同一 Query 的重复订单通过 `pair_count` 改变多目标的相对权重；仅一个目标时绝对频次会抵消。因此 `M/m` 是经过重加权的证据量，不是订单数或可信概率；原始订单量、独立 Query 数和 Pair 数另存。全量参与不等于按订单频率等权优化，与原始订单分布的 SFT 存在权重差异，后续有证据再单独比较频次权重。

按平均深度分配预算也有取舍：一个 POI 的少量精确 Query 可能被大量宽泛 Query 稀释。它解决的是深层权重无条件饱和，不是最优监督强度的证明。记录各 POI 的深度组成；若这类 POI 深层生成退步，单独比较归一化方式，不同时改粒度标签与地理项。

`b` 是冻结证据的损失权重，确实会改变不同 POI 的监督强度，必须记录并可消融；它不执行此前 E3 的 POI 与 Query 原始向量动态混合。不能用两者公式不同推断新权重一定有效。

无证据 POI 保存 `has_search_view=false, M=0, m=0, b=0`；有浅层证据但某深层 `b=0` 时仅关闭该层。搜索表示可用零占位，但不能把零占位当作合法概率分布进入质心估计。完整覆盖计数应同时报告 Query 类型、原始订单、Pair 和 POI 四个口径。

### 4.3 为什么不只取均值

对单位质心的 Query 余弦距离逐条加权求和，仍只依赖加权 Query 均值。v3 先映射到固定参照分布再聚合，允许一个 POI 在多个语义区域同时保留质量；它保留的是有限参照分辨率下的分布，不宣称无损还原多意图。

单目标 Query 通过 `h_p,l` 补充其目标 POI 的搜索表示；其他 POI 的同义或相近 Query 可映射到相近参照区域，从而改变共同分组代价。一个 Query 对应多个真实 POI 时，保留全部正向关系并按 `w_qp` 分配证据；若它只提供粗粒度信息，深层的 `g_l` 会减弱其影响，不强迫全部目标共享完整 SID。

## 5. 共享 POI 分配的双质心渐进量化

### 5.1 两种残差的定义

内容侧继续使用冻结 POI 变换与现有 Projection Residual，保持其与普通加法残差的区别。搜索侧取平方根表示：

```text
t_p,l = sqrt(h_p,l)
z_p,1 = t_p,1
mu_parent,l = sum_{p in parent} b_p,l * t_p,l / sum_{p in parent} b_p,l
z_p,l = t_p,l - mu_parent,l                 # l=2,3
```

- S2 的搜索 parent 为冻结 `S1`，S3 的搜索 parent 为冻结 `(S1,S2)`。地理 parent 另按 GID 协议处理，不混淆两者。
- 父组均值从当前层的 `h_p,l` 计算，不能从另一层不同路由权重的分布直接相减。每层拟合前构造一次，层内冻结；上层改变后必须重建下层，禁止缓存混用。
- `z` 是带符号的欧氏残差，已经不是概率分布；不再次逐行单位化，不把接近零的差异放大。
- `sum b=0` 的父组均值置零并登记无证据；其成员的搜索项权重为零。

父组只有一个有证据成员，或所有有证据成员的当前层分布相同时，`z=0`。这时直接用 `b*||z-V_k||²` 仍会偏好较小范数的 V，与本方案只利用剩余差异的意图不符。引入有效权重：

```text
b_eff_p,1 = b_p,1
b_eff_p,l = b_p,l * I[norm(z_p,l) > epsilon]   # l=2,3
```

`epsilon` 仅为 float32 数值容差，写入配置；不逐行单位化或把它调成语义筛选阈值。后续 assignment 与 V 更新统一使用 `b_eff`，不能只在一处关闭。分别统计“无日志证据”和“中心化后无剩余差异”，特别关注 S3 单例 parent 比例；若有效监督大幅减少，应受控比较关闭中心化，不能继续宣称全部关系都提供了深层监督。父组中心化的最终收益本身仍待 SFT 验证。

### 5.2 联合 assignment 与质心更新

第 l 层每个 code k 保存内容质心 `U_l,k` 和搜索质心 `V_l,k`，每个 POI 只有一个 assignment `s_p,l`：

```text
J_p,l(k) = 1 - dot(r_p,l, U_l,k)
         + lambda_l * b_eff_p,l * squared_l2(z_p,l, V_l,k)
         + eta_l * category_cost_p,l(k)
         + geo_cost_p,l(k)                 # 仅 S3；首轮使用旧地理算法
s_p,l = argmin_k J_p,l(k)
```

固定 assignment 后，内容单位质心与搜索欧氏质心分别更新为：

```text
U_l,k = normalize(sum_{p: s_p,l=k} r_p,l)
V_l,k = sum_{p: s_p,l=k} b_eff_p,l * z_p,l / sum_{p: s_p,l=k} b_eff_p,l
```

这里的中心更新式适用于对应的内容/搜索子目标，不据此宣称带同步地理图更新、平滑类别代价与重初始化的整个算法必然单调收敛。

Query 影响路径为：`冻结搜索证据 -> POI 联合分配改变 -> U/V 更新 -> 后续内容残差和 SID 改变`。删除独立的 Query assignment、Query–POI 同码惩罚和 Query 质心向 POI 质心收缩；搜索质心通过共享的 POI 成员保持对应关系，不使用维度/语义不同的 U 作为 V 的先验。

### 5.3 层内执行与边界处理

1. 从相同 POI-only PRQ 初始状态开始；各候选共享初始化来源和 seed。
2. 冻结本层内容残差、搜索残差、证据权重及父组；从初始 POI 分组统计 U/V 与类别代价。
3. 分块计算全 code 联合代价，稳定处理平局；更新同一套 POI assignment。首轮新配对 S1/S2/S3 均使用全 512 候选。
4. 用同一套成员更新 U/V，重算本层类别与地理统计，记录各目标分量和 assignment 变化。
5. 无有效搜索证据的非空 code 使用本层 `b_eff>0` 搜索表示的全局加权均值作 V 回退；整层无有效证据时搜索项关闭。空 POI code 按现有确定性规则重初始化，并用同一重初始化行同步建立 V；该行无有效证据则使用上述回退，不生成虚假的 Query 成员。
6. 若保留现有 Top-k refinement，软权重必须由联合代价产生，并用于同一批 POI 的 U/V 更新；不能直接调用旧 Query 独立 soft assignment。记录 hard/refinement 前后目标，不能把旧启发式当成新目标的下降保证。
7. 冻结本层 POI assignment 后，通过现有投影残差进入下一层，同时构造下一层的条件搜索表示。

类别 warm-up 可复用；搜索权重使用全局分层 `lambda_l`。旧 graph/query 权重不能不经标度核对直接解释为新搜索损失权重。M、温度、分类头结构、校准配置、lambda、refinement 等数值在实现配置中登记并经对应阶段验证；本文不虚构已选最优参数。

旧 `_assign_poi_s3` 先取内容距离 Top-32，再比较联合代价，不能原样用于此处全码分配。全 512 候选使新搜索视图有机会选择内容短名单之外的 code；`v3-query-off` 同样使用全 512，因此这是新实验共同的求解设置，不是 Query 独立收益。若因资源改用截断候选，两边必须同时修改、记录规则并重新配对，不能只扩大新方法的候选数。

## 6. 类别和地理如何结合

### 6.1 类别：保留软锚定

- S1 复用 `P(coarse_category | S1)` 软代价；S2 复用 `P(fine_category | S1,S2)` 条件软代价及平滑逻辑。
- 类别不拼入 BGE，不硬设 `S1=category_code`，S3 不另加类别分类损失。
- 新 Query D1/D2 语义不再由类别深度直接定义；类别统计可以提供弱监督，但不能垄断粒度标签。
- 类别纯度改善只是结构证据。保留该模块的首轮目的是隔离 Query 改动，不能据此宣称其独立检索增益已证实。

### 6.2 首轮 v3-query：固定旧地理算法，重新适配新父组

保留 v2.1 的 S3 局部 Geo 特征、困难边规则、权重与 GID-parent 定义；替换的是 Query 监督项。由于 S1/S2 会改变，需要按各候选的新父组重新计算地理统计和困难边，不能复用绑定旧 A4 assignment 的数组。困难边保护关系沿用相同冻结 Train 来源，转换到全局 POI 行号后使用，不能把旧 P4 `node_row` 接到新全量 Query 上。配对对照遵循相同重建规则；候选搜索范围的共同变更见第 5 节，不将“保留地理算法”写成与旧 S3 求解过程完全相同。

### 6.3 后续 v3-geo：只给远距离同码冲突加代价

在已确认 Query 收益后，另开受控候选，以真实米制距离替换旧的 Geo 特征/困难同码组合。语义先固定，GID 版本只在同 `(GID6,S1,S2)` 内构造有界稀疏关系：

```text
L_geo = gamma * sum_{(p,p') in E_parent} omega_p,p' * I[s_p,3 == s_p',3]
omega_p,p' = clip((distance_m(p,p') - radius_m) / radius_m, 0, 1)
```

- 半径内地理代价为零，超过半径才惩罚同 S3；边数、单 POI 总权重有界。
- 近距离允许共享，不奖励或强迫同码；不同店铺、门址仍可由内容与具体 Query 区分。
- GID 已区分的远距离实体不重复贡献主要收益；不把 GID 或解码约束本身算作本版创新。
- 该项在 `v3-geo` 中替换旧 Geo/hard 组合，不能一边保留近距离困难边强制分离、一边宣称已取消近距离排斥。
- 第一轮 Query 配对实验不同时调整距离半径。半径、稀疏采样和权重在后续配置中固定，通过 Validation 验证；不构造父组内全量平方规模 POI 对。
- 监控完整 ID 碰撞、Dedup 长度/难度和完整 POI HR/NDCG，防止只改善基础桶却加重后缀预测。

拟定输出包括：全量 Query 行映射与 Raw embedding 引用、标签/路由表、参照点、Query 稀疏权重、POI 分层搜索分布/证据量、父组均值、U/V、POI assignment、目标轨迹、最终标识及各阶段 manifest。文档只登记字段，不提前生成空 checkpoint、空成功标记或批量占位文件。

工程上使用 mmap/Parquet 分块读写，累加使用 float32；分布是否密集物化须先估算 `POI数 × M × 层数 × dtype` 内存。临时文件、缓存、日志进入项目输出目录；平台任务遵循仓库 workflow 的短 TMPDIR、资源检查和准备流程。

旧 S3 的图惩罚 helper 会物化 `POI数 × code数` 矩阵，716,245×512 的单个 float32 矩阵约 1.37 GiB；即使外层设 `chunk_rows` 也不能消除此分配。新路径复用其代价规则，按当前 POI 块和稀疏邻边计算；困难边构建还需检查最大 parent 的平方规模临时矩阵，输出 Top-20 不代表构建内存必然有界。

用户已要求准备实施、优先复用并按实验结果修订方案。本次完成设计复核与代码规划，训练/全量处理尚未执行。开发先做 V3-DATA；粒度头与搜索量化核心可在统一契约下分别开发，不因真实人工标签尚缺而停住全部工程工作，也不把缺标签、缓存或代码的阶段标成 READY。

量化器的必要合成验证：

1. 搜索权重为零时，在相同配置与初始化下复现同代码的内容+类别/地理对照；类别/地理也关闭时再对照 POI-only PRQ，不能把前者误称 A0。

3. 一个粗 Query 对应多个 POI 时仅有浅层监督；真实多正边全部保留，未命中 POI 不凭空作为负例。
4. 构造原始向量均值相同但参照分布不同的样例，确认搜索距离能区分该例；不外推成任意分布均可区分的证明。
5. U/V 使用相同 POI assignment，移除 Query 独立 code；S2/S3 的 parent 均值来自对应层视图，变更上层后拒绝复用旧残差。
6. 空 code、无证据 code、零残差与非有限输入都有明确处理；零残差的搜索代价对所有候选均为零，不能偏好小范数 V。hard/refinement 分别记录目标，不能仅报告一致率。
7. 后续地理测试验证：半径内零惩罚、超半径同码惩罚、异码不罚、其他 parent 不参与，以及不存在近距离强制合并。

## 9. 首轮实验与收益归因

### 9.1 先做一对真实 SFT

| 候选 | 内容/类别/地理 | Query | 目的 |
|---|---|---|---|
| `v3-query-off` | PRQ + 当前类别软代价 + 当前 S3 地理/困难边算法 | 所有 Query 项关闭 | 公共结构对照；它不是已有 A0 checkpoint |
| `v3-query` | 同上，按各自新前缀重建依赖资产 | 全量软粒度搜索分布 + 共享 POI assignment | 检验新 Query 链路的净收益 |
| 已有 A0/A4 | 冻结既有结果 | 保持原样 | 历史参照，不代替上述配对控制 |

两组固定 active 目录、POI BGE、512³、GID/Dedup 规则、原始订单、history10、Qwen3-0.6B 初始模型、3 epoch、cutoff=1024、全局训练 batch、Beam=10 和评测业务键。SID 改变后需要重新映射目标及历史 identifier 并重新 SFT，不能直接拿旧 Qwen checkpoint 比较新 SID。

聚类初始化、优化日程和 SFT 新增 Token 初始化规则显式配对。标识长度或 packing 变化可能使步数略有差异，应登记实际样本/Token/步数，不将三轮训练误说成完全相同步数。

新增求解器的候选范围、hard/refinement 日程与停止规则也要两边一致。第一步先验证 hard-only 联合更新；若保留 Top-k，再实现联合代价权重并在真实 SFT 前冻结共同设置。目标是尽快完成可信配对，不先穷举所有算法组合。全量软粒度为默认主候选；若标签准备成为主要等待项，可先载入明确命名的旧路由对照验证搜索分布/共享分配，必须记录其旧筛选覆盖、旧标签含义，不能称为已完成全量 v3 或新粒度模型。

### 9.2 评测与后续消融

- 首先评测固定 Validation 10k，以及已见 Query/未见 Pair、新 Query/已见目标、长尾目标、冷目标四个冻结互斥集合；无约束和同一全目录约束分别比较。
- 主指标为完整原始 POI 的 HR@1/3/5/10、NDCG@10；同时记录合法率、Bucket 覆盖、Dedup 和逐层 Qwen 诊断。不得只报告基础桶或合法率。
- 保留逐请求配对结果，报告增减命中和配对区间；重复 Query 的依赖可通过 Query 分组重采样检查。静态 probe 与粒度分类准确率都不能替代 SFT 指标。
- 首轮若有稳定正向，再分别比较旧筛选覆盖与全量覆盖、硬路由与软路由、Query 均值与搜索分布、无条件中心化与父组中心化、旧地理与距离冲突项。每次只改变对应因素，不一次铺开全部组合。
- 候选/参数由 Validation 选择，Test 仅作最终确认。若首轮没有收益，先用完整 POI 与逐层生成结果确定损失位置，不靠继续提高图一致率宣布成功。

## 10. 风险、相关工作与创新边界

主要待验证点：弱标签可能复制日志偏差；固定参照过粗可能抹掉实体差异；稀疏 POI 搜索分布有采样噪声；父组中心化可能移除有用信号；对有 Query POI 的重组可能损害冷目标；局部地理放松可能增加 Dedup 负担。对应消融和切片评测见第 9 节，本文不承诺任何一项必然正向。

相关工作用于界定设计来源与差异：

- [BMI，ICML 2024](https://arxiv.org/html/2405.10974v2)：从 Query 条件分布讨论生成索引，其具体方案使用 Query 均值和层次聚类，也讨论多峰分布的限制。故“Query 参与索引”不是本版独占贡献。
- [ICEGR，2026 预印本](https://arxiv.org/html/2608.29652v3)：在 SID 构建前使用 Query–商品关系及历史 Query 聚合表示。故“增加搜索视图”或 Query 聚合本身不足以证明新颖性。
- [BoDS，SIGIR eCom 2026](https://sigir-ecom.github.io/eCom26Papers/paper_753.pdf)：用行为集合产生 specificity 监督，再训练文本模型推广到缺少行为的 Query。其集中程度分数不等同于本版的三级监督深度，不能直接当作可用三分类模型。

本版待检验的贡献是：**软粒度控制真实搜索证据进入的层级，在同一 POI 前缀下保留搜索分布的剩余差异，与内容视图共同决定唯一一套层级编码，再用独立的局部地理约束处理空间冲突。** 组件组合不自动构成创新，必须通过相关工作比较和真实生成式消融证明有效性。
